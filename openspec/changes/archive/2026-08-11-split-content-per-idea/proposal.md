# Split Content Per Idea

## Why

Today all idea metadata lives in a single `content/ideas.json` file while each idea's body is a flat `content/ideas/{id}.md` file. As the catalogue grows, editing, reviewing, and versioning one idea requires touching a monolithic JSON file that also carries the site configuration, and the build has no per-idea structure to work from. Splitting site config out of the idea catalogue and giving every idea its own self-contained directory (metadata + body) makes content atomic, reduces merge conflicts, and lets the build club the per-idea JSON files together at build time.

## What Changes

- **BREAKING**: Move the `site` object out of `content/ideas.json` into a dedicated `content/site.json` (same fields: `title`, `description`, `language`, `base_url_live`, `base_url`).
- **BREAKING**: Replace the `ideas` array in `content/ideas.json` with one self-contained directory per idea: `content/ideas/<idea-id>/meta.json` (the idea metadata) and `content/ideas/<idea-id>/meta.md` (the idea body). `content/ideas.json` is deleted.
- `build.py` discovers `content/ideas/*/meta.json`, loads each record, and clubs them into the `ideas` list at build time, then uses the combined data throughout (slug enrichment, catalogues, pages, sitemap).
- `build.py` reads site configuration from `content/site.json` instead of the `site` key of the removed `ideas.json`.
- **BREAKING**: Rename the generated client-side index payload `site/index.json` → `site/ideas.json` (same payload shape: `site`, `ideas`, `catalogues`). `theme/app.js` fetches `ideas.json` instead of `index.json`.
- No change to generated page URLs, templates, catalogue structure, or the Marathi display literals.

### Modified Capabilities
- `content-model`: The single source of metadata becomes `content/site.json` + per-idea `content/ideas/{id}/meta.json`; the body moves to `content/ideas/{id}/meta.md`. REQ-CM-001, REQ-CM-002, REQ-CM-003 change; REQ-CM-004 unchanged.
- `build-engine`: Input loading clubs per-idea `meta.json` files and reads `content/site.json`; slug-enrichment references the renamed output `ideas.json`. REQ-BE-001, REQ-BE-003 change.
- `site-output`: The client-side index payload is generated as `site/ideas.json` instead of `site/index.json`. REQ-SO-005 changes.
- `client-side-search`: The home page fetches `ideas.json`; catalogue-page independence from the payload and graceful-degradation behaviour are unchanged but reworded to the new filename. REQ-CS-001, REQ-CS-003, REQ-CS-005 change.

## Impact

- Files created/updated:
  - `content/site.json` (new)
  - `content/ideas/<id>/meta.json` and `content/ideas/<id>/meta.md` (new, per idea)
  - `content/ideas.json` (deleted)
  - `build.py` (content loading, site config loading, output filename)
  - `theme/app.js` (fetch `ideas.json`)
  - `README.md` (content model + generated site docs)
  - `openspec/config.yaml` (project context: build engine input description)
- Generated output `site/ideas.json` replaces `site/index.json`; `site/` is regenerated by the build.
- No dependency changes; no template changes; no URL changes.
- Constraint: `build.py` must not write into `content/` (REQ-CM-004 still holds - content stays user-generated input).
