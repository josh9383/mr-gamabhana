# Site Output Spec

## ADDED Requirements

### Requirement: [REQ-SO-001: Home page]
The build SHALL generate `site/index.html` from `templates/index.html.j2`, rendering the site title, description, catalogue links, and placeholder containers for the client-side catalogue groups. Its canonical URL SHALL be the site root.

#### Scenario: Home page is generated
- **WHEN** the build completes
- **THEN** `site/index.html` exists, contains the site title and description, and declares a canonical URL pointing at the site root

### Requirement: [REQ-SO-002: Yukti pages with HTML and Markdown copies]
The build SHALL generate, for every yukti, a directory `site/yuktis/{id}/` containing `index.html` and `index.md`. The HTML page SHALL render the yukti metadata, tags linking to catalogue pages, and the converted Markdown body. The Markdown copy SHALL reproduce the yukti metadata as YAML front matter plus the body.

#### Scenario: Yukti directory contains both copies
- **WHEN** the build processes yukti with id `angles`
- **THEN** `site/yuktis/angles/index.html` and `site/yuktis/angles/index.md` exist
- **AND** the HTML page includes links to the board, standard, subject, category, concept, and prop catalogue pages

### Requirement: [REQ-SO-003: Catalogue landing and individual pages]
The build SHALL generate a landing page at `site/{path}/index.html` and one individual page at `site/{path}/{slug}/index.html` for `boards`, `standards`, `subjects`, `categories`, `props`, and `concepts`. Individual pages SHALL list the yuktis belonging to that item and support client-side filtering.

#### Scenario: Catalogue pages are generated for every item
- **WHEN** the build completes
- **THEN** `site/boards/`, `site/standards/`, `site/subjects/`, `site/categories/`, `site/props/`, and `site/concepts/` each contain a landing page and one page per item
- **AND** each individual page lists every yukti that belongs to that item

### Requirement: [REQ-SO-004: Yuktis catalogue landing page]
The build SHALL generate `site/yuktis/index.html` listing every yukti as a filterable card with its title, description, and URL.

#### Scenario: All yuktis are listed on the landing page
- **WHEN** the build completes
- **THEN** `site/yuktis/index.html` contains one card per yukti linking to `site/yuktis/{id}/`

### Requirement: [REQ-SO-005: Client-side index payload]
The build SHALL generate `site/index.json` containing the `site` object, the enriched `yuktis` index (id, title, description, metadata, slugs, and URL), and the `catalogues` for all six catalogue types. The payload SHALL be encoded as UTF-8 JSON with indentation.

#### Scenario: index.json matches generated pages
- **WHEN** the build completes
- **THEN** `site/index.json` exists and its `yuktis` entries reference URLs that match generated pages
- **AND** its `catalogues` contain the same items and URLs as the generated catalogue pages

### Requirement: [REQ-SO-006: Sitemap]
The build SHALL generate `site/sitemap.xml` listing the home URL, the yuktis landing URL, every yukti page URL, every catalogue landing URL, and every individual catalogue page URL, each prefixed with the site's `base_url`.

#### Scenario: Sitemap covers generated pages
- **WHEN** the build completes
- **THEN** `site/sitemap.xml` contains a `<loc>` entry for every page generated by the build

### Requirement: [REQ-SO-007: Static assets copied to site]
The build SHALL copy `theme/style.css` and `theme/app.js` into `site/assets/` so all pages reference assets from the generated site.

#### Scenario: Assets are available in site
- **WHEN** the build completes
- **THEN** `site/assets/style.css` and `site/assets/app.js` exist
- **AND** every generated HTML page references them via the site's `base_url`

### Requirement: [REQ-SO-008: SEO metadata on pages]
Generated HTML pages SHALL declare `lang` from the site language, a unique `<title>`, a `<meta name="description">`, and a self-referencing `<link rel="canonical">`. Yukti and catalogue pages SHALL render a breadcrumb navigation.

#### Scenario: Pages expose SEO metadata
- **WHEN** any generated HTML page is inspected
- **THEN** it declares the site language, a title, a meta description, and a canonical URL matching its own location

### Requirement: [REQ-SO-009: Self-contained output artifacts]
Every generated artifact SHALL be entirely self-contained with no shared runtime cross-dependencies: each page SHALL reference only assets under the site's own `base_url` path, and no page SHALL depend on another page's file at runtime.

#### Scenario: Pages are atomic and self-contained
- **WHEN** any generated page is hosted standalone under its `base_url`
- **THEN** it renders correctly using only its own markup, `site/assets/style.css`, and `site/assets/app.js`
